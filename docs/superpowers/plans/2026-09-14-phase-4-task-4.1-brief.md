## Decisions

1. **URL scheme.** Versioned, case-scoped paths:
   - `GET /api/v1/directory`
   - `GET /api/v1/cases/{case_id}/upload`
   - `GET /api/v1/cases/{case_id}/run?run=`
   - `GET /api/v1/cases/{case_id}/analysis?run=`

   The case is the authorisation resource, so it goes through the same
   private-404 path that `run_id` uses today. The `/api/v1/` prefix gives 4.5 a
   single prefix to route at the edge. Page URLs keep `?case=`. A caseless
   Upload, Run or Analysis view sends no request and renders `unavailable`.
2. **Versioning.** The major version lives in the path only. Documents carry no
   version field and there is no negotiation header.
   - Until Phase 4 is accepted, only the task that owns a field may add one: a
     model change, a regenerated schema and an updated pinned key set. For
     example, 4.2 adds `chrome.actions` and 4.4 adds page references.
   - After acceptance, a breaking change means `/api/v2`.
3. **Refusal body.** `RefusalBody{code: RefusalCode, clears: str}`, where
   `clears = CLEARS[code]`.
   - `CLEARS` is a complete table of host constants in `server/api/wire.py`,
     never formatted. `server/refusals.py` stays code-only.
   - Status codes keep `_STATUS`. An anonymous request gets 401
     `NOT_AUTHENTICATED` before any store connection opens.
   - A malformed `case_id` gets `CASE_NOT_FOUND`, and a malformed `run` gets
     `RUN_NOT_FOUND`. Identity is still derived first.
   - A run belonging to another case gets `RUN_NOT_FOUND`.
   - An undeclared path or method under `/api/` answers 404 or 405 with the one
     new code, `ENDPOINT_NOT_FOUND`.
   - `/api/runs/{run_id}/events` keeps its path in 4.1 and adopts this body.
4. **Retiring `/api/runs/{id}`.** Delete `read_run` and `RunDocument`.
   - `NodeView` and `EdgeView` move into the Run body.
   - Retarget the pinned tests to `/api/v1/cases/{case}/run?run=`: node state,
     gate, digest, refusal and budget in `tests/test_api_routes.py`, plus
     `tests/test_canonical_readers.py` and the `{"refusal": …}` assertion in
     `tests/test_disabled_routes.py`.
   - Reason: the guardrail forbids pretending `/api/runs` is a section document,
     and two refusal bodies cannot coexist.
5. **Chrome.** The server computes authority facts only:
   `Chrome{subject: {case_id, title} | null, served_role: {global_role, standing | null}}`.
   - The client composes the ribbon, brief, tabs, verdict and rail from section
     constants and body facts (`frontend/src/chrome/compose.ts`).
   - The served role is shown and enables nothing.
   - 4.1 has no actions.
6. **Envelope.** Every key is required:
   `{chrome, body, observed_at, observed_empty, status: "complete" | "partial", notes: SectionNote[]}`.
   - `SectionNote` is a closed enum: `LIST_TRUNCATED`, `ROUTE_NOT_PINNED`,
     `HANDOFFS_PENDING`.
   - `observed_at` is the store's `now()` inside the read unit.
7. **Browser validation.** A small closed-shape DSL in
   `frontend/src/wire/v1/shape.ts` provides `object`, `array(max)`,
   `string(max, pattern)`, `uuid`, `datetime`, `int`, `number`, `bool`,
   `literal`, `enumOf` and `nullable`. It produces both the validator and the
   type (`Infer<>`), with no dependency.

   | Response | Refusal |
   |---|---|
   | An undeclared or missing key at any depth, a wrong type, or a value over its bound | `WIRE_SHAPE_INVALID` (replaces `WIRE_KEYS_MISMATCH`) |
   | A document whose case or run differs from the request | `WIRE_IDENTITY_MISMATCH` |
   | A body that is not JSON, or a legacy refusal | `RESPONSE_INVALID` |
8. **Cross-language contract.** `python -m server.api.wire` prints the JSON
   Schema of the four documents and `RefusalBody`, committed at
   `frontend/src/wire/v1/schema.json` and listed in `.prettierignore`.
   - The backend test proves the committed schema equals the models' schema. It
     also refuses schema keywords the DSL cannot express.
   - The frontend test normalises each DSL spec to the same subset and proves it
     equals the file. The subset covers type, properties, required, enum,
     nullability, `maxLength`, `maxItems`, pattern and format.
   - Both sides validate the four v1 demo fixtures: Pydantic in pytest, and the
     validator in vitest.
9. **Disabled sections and fixtures.**
   - `ENABLED_SECTIONS` lives in `frontend/src/app/sections.ts`.
   - A disabled section renders `unavailable`, with no request and no tail, in
     every mode including demo. The rail marks it unavailable.
   - Its wire types, views, fixtures and unit tests stay dormant and unmounted.
   - Workbench specs that drive a disabled section assert `unavailable` instead.
   - The demo middleware answers only the v1 paths. `transport.ts` adds
     `fixture` only when `import.meta.env.MODE === "demo"`.
   - `tests/test_frontend_modes.py` proves the production `dist` contains no
     fixture file, no `fixture=` string and no demo route.

## Contracts

- All models use `ConfigDict(extra="forbid", frozen=True)`.
- Every string and list is bounded.
- TypeScript names match the Python names.
- Hashes match `^[0-9a-f]{64}$`.

```python
RunStatus = Literal["RUNNING","COMPLETE","FAILED","BLOCKED"]
class RunSummary: run_id: UUID; status: RunStatus; created_at: AwareDatetime

class CaseRow: case_id: UUID; title: str; created_at: AwareDatetime
    standing: Standing; live_sources: int; latest_run: RunSummary | None
class DirectoryBody: cases: list[CaseRow]                     # <=200, else partial LIST_TRUNCATED
class SourceRow: source_id: UUID; filename: str; document_sha256: str
    admitted_at: AwareDatetime; withdrawn_at: AwareDatetime | None
    extractor_identity: str | None; set_versions: list[int]
class SetVersion: version: int; fingerprint: str; member_count: int
class UploadBody: case_id: UUID; sources: list[SourceRow]; set_versions: list[SetVersion]
class RunSubjectView: issuer_id: str; issuer_name: str; reporting_period: str; analysis_date: str
class GateView: gate: Gate; state: GateState
class AttemptView: attempt_id: UUID; route_node_id: str; ordinal: int | None
    started_at: AwareDatetime; accepted: bool
class RunView: run_id: UUID; status: RunStatus; created_at: AwareDatetime
    route_digest: str | None; build_id: str | None; source_set_version: int | None

    accepted_at: AwareDatetime; qa_status: str; committee_status: str
```

**Rules for the contracts:**
- `screening_only` means `decision_scope == SCREENING_ONLY`, the same rule
  `render.py` applies.
- `limitation_flags` is always present and always rendered.
- `model_analysis` renders as text, never as markup.
- Directory lists only cases where the actor holds live standing. A global
  ADMIN without membership sees none.
- Analysis reads through a new public
  `accepted_handoff(...) -> (markdown, CanonicalRecord)` in
  `server/methodology/canonical.py`, which wraps `_verified_accepted` and does
  no re-anchoring (§42.4).
- Unaccepted route nodes make the Analysis document `partial`, with
  `HANDOFFS_PENDING`.

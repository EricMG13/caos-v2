## Scope

1. One migration, `0013_run_work`, with:
   - a per-run work row carrying a fencing token and a lease;
   - a write-once `attempt_refusals` table;
   - the `CANCELLED` run status and the `RUN_CANCELLED` event.
2. A fence under `lock_run` on `start_attempt`, `reserve`, `accept_attempt` and
   every terminal transition. `record_outcome` stays unfenced, because money is
   always recorded.
3. The terminal decision moves under the run lock. The store refuses COMPLETE
   while any pinned node is unaccepted.
4. Recovery accepts, blocks or explains a billed answer from its stored body,
   without calling again. This closes the Phase 2/3 crash-gap re-pay.
5. `server/engine/worker.py`: a polling loop, the lease, cancellation, a clean
   stop on SIGTERM, and `make dev-worker`.
6. Decision §49, ledger and handoff.

**Non-scope:**
- Other Phase 4 tasks: 4.1 wire and refusal body; 4.2 command endpoints,
  idempotency and audit; 4.4 events and section reads (except that
  `RUN_CANCELLED` joins the stream's `TERMINAL` set); 4.5 packaging, readiness
  and the browser journey's deterministic provider.
- Infrastructure: no broker, Redis, LISTEN/NOTIFY, checkpointer, second database
  or graph framework.
- No concurrent nodes within a run.
- No `artifacts` immutability trigger.
- No automatic resume of a BLOCKED or CANCELLED run.

## Decisions

**D1. Claim per run, not per node.** One lease holder drives a run's frontier in
order, exactly as `run_route` does now.
- **Why:** the only other writer is then a stale holder, and the fence refuses
  it. That makes the terminal snapshot, "acceptance does not recompare
  upstream" and `call_time_identity`'s `created_at > started_at` exact.
- **Why the ordering holds:** a stale holder's fenced write either commits
  before the new claim commits, or it waits on the work row and fails the token
  check.
- **Rejected:** a claim per node needs predecessor fencing and event ordering,
  for parallelism nothing needs.

**D2. Schema** (`0013_run_work.sql`, appended to `MIGRATIONS` per §20a):

```sql
CREATE TABLE run_work (
  run_id uuid PRIMARY KEY REFERENCES runs (run_id),
  state text NOT NULL CHECK (state IN ('QUEUED','CLAIMED','STOPPED','DONE')),
  lease_token bigint NOT NULL DEFAULT 0,            -- fencing; +1 on every claim
  worker text CHECK (octet_length(worker) <= 128),  -- diagnostic only
  lease_expires_at timestamptz,
  requested_at timestamptz NOT NULL DEFAULT now(),
  cancel_requested_at timestamptz,
  stop_code text CHECK (stop_code ~ '^[A-Z][A-Z0-9_]{0,63}$'),
  CHECK ((state = 'CLAIMED') = (lease_expires_at IS NOT NULL AND worker IS NOT NULL)),
  CHECK ((state = 'STOPPED') = (stop_code IS NOT NULL)));
ALTER TABLE run_attempts ADD COLUMN lease_token bigint;   -- pre-0013 rows keep NULL
CREATE TABLE attempt_refusals (attempt_id uuid PRIMARY KEY REFERENCES run_attempts,
  code text NOT NULL CHECK (code ~ '^[A-Z][A-Z0-9_]{0,63}$'),
  recorded_at timestamptz NOT NULL DEFAULT now());  -- plus 0007-style immutability triggers
-- runs status CHECK += 'CANCELLED'; run_events name CHECK += 'RUN_CANCELLED'
```

- Refusal codes are checked by shape, so a new code needs no migration.
- **Who can reclaim:** any worker, but only a `QUEUED` row or a `CLAIMED` row
  with `lease_expires_at <= clock_timestamp()`. The token, not the clock, is the
  fence.
- **Lock order:** case, then run (`lock_run`), then `run_work`. The claim takes
  only `run_work` and commits on its own.

**D3. Exact predicates.** The fence is `require_lease(conn, run_id, lease)` in
`server/store/work.py`. It runs after `lock_run`, in the same transaction as the
write it guards.

```sql
-- claim (committed alone)
UPDATE run_work w SET state='CLAIMED', lease_token=w.lease_token+1, worker=%s,
  lease_expires_at=clock_timestamp()+make_interval(secs=>%s)
 WHERE w.run_id=(SELECT run_id FROM run_work WHERE state='QUEUED'
   OR (state='CLAIMED' AND lease_expires_at<=clock_timestamp())
   ORDER BY requested_at, run_id LIMIT 1 FOR UPDATE SKIP LOCKED)
   AND (w.state='QUEUED' OR w.lease_expires_at<=clock_timestamp())
 RETURNING w.run_id, w.lease_token;
-- fence + renew (lease given): rowcount 1, else LEASE_NOT_HELD
UPDATE run_work SET lease_expires_at=clock_timestamp()+make_interval(secs=>%s)
 WHERE run_id=%s AND state='CLAIMED' AND lease_token=%s RETURNING cancel_requested_at;
-- fence (lease None): SELECT 1 FROM run_work WHERE run_id=%s FOR SHARE -> any row: LEASE_NOT_HELD
```

A run with no work row can still be driven by a direct caller (harness, tests).
Once a run is enqueued, only its lease holder can write to it.

| Write | Predicate added | Extra |
|---|---|---|
| `start_attempt` | fence; `cancel_requested_at IS NULL`, else `RUN_CANCEL_REQUESTED` | stores `run_attempts.lease_token` |
| `reserve` | fence; same cancel predicate | — |
| `record_outcome` | **none**: money commits even for a stale or terminal holder | — |
| `accept_attempt` / `_accept_artifact` | fence (not gated on cancel) | unique `(run_id, route_node_id)` stays the backstop |
| `complete_run` / `block_run` / `fail_run` / `cancel_run` | fence; `_transition` also sets `run_work.state='DONE'` when a row exists | see the notes below |
| `check_call` (before transport) | fence as a non-locking read | stops a knowingly stale call; not the safety guarantee |

- **COMPLETE** requires every pinned node of `approved_run_input` to have an
  artifact, else `RUN_NODES_UNACCEPTED`.
- **BLOCKED or COMPLETE with an `accepted=` snapshot:** the set re-read under the
  lock must equal the snapshot, else `RUN_TERMINAL_STALE`.

New codes: `LEASE_NOT_HELD`, `RUN_CANCEL_REQUESTED`, `RUN_NODES_UNACCEPTED`,
`RUN_TERMINAL_STALE`.

**D4. Enqueue and cancellation (interfaces only; the endpoints are 4.2).** The
caller owns the commit, so each call rides the command's governed write and
audit event.

| Function | Effect |
|---|---|
| `enqueue_run(conn, run_id) -> bool` | `INSERT … ON CONFLICT DO NOTHING`, only for a RUNNING run, under `lock_run` |
| `requeue_run(conn, run_id) -> bool` | moves `STOPPED` back to `QUEUED` and clears `stop_code`; this is what retry calls |
| `request_cancel(conn, run_id) -> bool` | sets `cancel_requested_at` once; a `QUEUED` or `STOPPED` row ends the run `CANCELLED` with `RUN_CANCELLED` in the same transaction |

- A cancel is a request and never interrupts a call already in flight. That
  call's bill commits, and a valid answer is accepted.
- The next `start_attempt` or `reserve` refuses, and the worker runs
  `cancel_run(lease)`.
- Browser disconnect cannot cancel a paid call: the API never imports
  `run_route`, a provider or a transport, and commands only write `run_work`.
  This is enforced by a test.

**D5. Lease length.**
- Default 300 s, renewed by every fenced write and at the top of each frontier
  pass.
- A test pins `LEASE_SECONDS > 2 * provider.TIMEOUT_SECONDS`.
- `TIMEOUT_SECONDS` bounds each socket operation, not the whole call, so a
  trickling response can outlive a lease. That costs at most one extra paid
  call (bounded by the ceiling and the 256-attempt cap) and never a duplicate
  acceptance. Recorded in the ledger.

**D6. Crash recovery by boundary.**

| Crash after… | Durable facts | Next claim (token t+1) | Spend |
|---|---|---|---|
| claim | row CLAIMED, expired | recomputes the frontier | none |
| `start_attempt` | attempt, no reservation | orphan keeps its ordinal; `check_call` refused any call; new attempt | none |
| `reserve` / transport / before `record_outcome` | reservation, no outcome | indeterminate call; the reservation stays counted; new attempt (§16) | possible = reservation |
| `record_outcome` (bill and diagnostic) | billed, unaccepted, no `attempt_refusals` row | **replays the stored body**: accept, end BLOCKED, or record `attempt_refusals` and STOP; no call | known bill |
| acceptance | artifact | node is COMPLETE by recomputation | — |
| last acceptance, before terminal | every node accepted | `complete_run(lease)`: one `RUN_COMPLETE` | — |
| terminal transition | DONE written in the same transaction | nothing to claim | — |

**D7. Closing the crash-gap re-pay.**
- `canonical.blocked_verdict` generalises to `replay_billed(conn, blobs, bundle,
  *, run_id, route, route_node_ids) -> Replayed | None`.
- `Replayed` carries `(attempt_id, verdict: ANSWERED|BLOCKED|REFUSED, outcome,
  code)`.
- It walks billed, unaccepted, unrefused attempts in ordinal order, using the
  same post-call checks as `execute_handoff`, factored into one private
  function.
- The identity must equal `host_identity(attempt)` now. A soft input accepted
  after the attempt started gives REFUSED `ROUTE_IDENTITY_INVALID`: the answer
  is explained, not accepted.
- Store faults are never recorded as refusals.
- A truncated answer or a provider refusal stores no body, so it is never
  replayed.
- The live `_run_node` records `attempt_refusals` for any non-fault refusal
  raised after the call outcome, so a retry never replays a known refusal. A
  retry makes exactly one new attempt.

**D8. Terminal decision.**
- `run_route` computes `node_states` in a read unit, then calls `complete_run` or
  `block_run(…, accepted=frozenset(nodes), lease=…)`. That call re-derives the
  accepted set under `lock_run`.
- `RUN_TERMINAL_STALE` triggers one more pass.
- `complete_attempt` now refuses while other pinned nodes are unaccepted.
- The Phase 2 ledger entry closes.

**D9. Worker.**
- `work_once(conn, blobs, *, execution_for, config, stopping) -> UUID | None`
  claims at most one run and drives `run_route` with `Execution(..., lease=lease)`.
  It maps each outcome:
  - `LEASE_NOT_HELD`: drop the run.
  - `RUN_CANCEL_REQUESTED`: `cancel_run`.
  - `RUN_NOT_RUNNING`: nothing to do.
  - A store fault: `release`, otherwise let the lease expire.
  - Any other refusal: `stop(lease, code)`.
- `run_worker(config, *, execution_for, stopping) -> int`:
  - polls every 1 s with ±20% jitter;
  - backs off on `STORE_UNAVAILABLE`, with a cap;
  - on SIGTERM, sets `stopping`, which is checked between passes and never
    during transport, then releases the claim.
- Liveness is the process itself. Readiness is 4.5.
- Polling, not LISTEN/NOTIFY: expiry has to be polled anyway, and NOTIFY would
  need a second dedicated connection.
- `main()`:
  - reads `CAOS_DATABASE_URL` and `CAOS_BLOB_ROOT`, runs `apply_schema`, and
    verifies the bundle;
  - builds `OpenRouter.from_environment()` and a dated price from
    `CAOS_MODEL_PRICE` (§49, the worker's price source under §40);
  - exits 2 with the typed code, and makes no call, if either is missing.
- `make dev-worker` runs `$(PY) -m server.engine.worker`.

## Two-worker interleavings (A holds token t; B claims t+1 after expiry)

| # | Interleaving | Predicate that decides it | Result |
|---|---|---|---|
| I1 | A and B poll one queued run | `FOR UPDATE SKIP LOCKED` + token +1 | one claim |
| I2 | A loses the lease before `start_attempt` | fence `lease_token=t` | A refused; no attempt |
| I3 | A started; B reclaims; A reserves | fence in `_reserve` | no reservation; `check_call` refuses; no call |
| I4 | A calling; B reclaims, pays and accepts; A returns | unfenced `record_outcome`; fenced `_accept_artifact` | two known bills, one artifact |
| I5 | A records before B's pass-start replay | replay finds a billed, unaccepted attempt | B accepts A's answer; no second call |
| I6 | A records after B's replay read, before B reserves | none (no lock across transport) | double pay, one acceptance: recorded residual |
| I7 | B claims while A's accept holds the row | SKIP LOCKED; A's renewal fails B's outer predicate | A accepts; B claims nothing |
| I8 | A decides a terminal state after reclaim | fence in `_transition` | A refused |
| I9 | Cancel lands during A's call | cancel predicate only at start and reserve | bill and acceptance, then CANCELLED |
| I10 | Cancel and expiry, then B claims | B's `start_attempt` refuses cancel; `cancel_run(t+1)` | one `RUN_CANCELLED`; A's late accept refused |
| I11 | `request_cancel` on a QUEUED or STOPPED row vs a claim | both need the row lock; the transition writes DONE | either claimed or cancelled |
| I12 | Unleased writer on an enqueued run | `run_work` row exists | `LEASE_NOT_HELD` |

## Exit checks

- Every RED fails for its semantic reason before the production change.
- `make test-postgres-races` and the serial backend gate pass. Populated-upgrade
  migration tests pass.
- Killing and restarting the worker at each D6 boundary gives:
  - one artifact per node;
  - bills equal to known calls, and reservations standing for indeterminate
    calls;
  - one terminal event;
  - a `stop_code` or `attempt_refusals` row for every unaccepted billed attempt.
- A billed answer is never paid again after a crash. Only I6 can double-pay, and
  it is recorded.
- Deterministic providers only; zero live calls; no new dependency.
- Ordinary exact-range review per slice. GitNexus is refreshed before 4.3a and
  after 4.3f.

## Findings at base

- `Revision` (`server/deliverable/canonical.py:52`) is caller-supplied; its
  `revision_id` is a caller label (`BoundaryText`) and nothing stores a revision.
- `sign_opinion` signs a caller-supplied `payload_sha256`
  (`server/deliverable/filing.py:68`); `freeze` hashes caller-supplied bytes
  (104) and stores only the digest; the payload is derived in its own read unit
  before the freeze's governed write (ledger: "proves the store at freeze and
  verification, not continuously").
- The narrative is one free `BoundaryText`: a figure can be typed into it with no
  reference, and the docstring's "refuses a narrative asserting an uncited
  figure" is not enforced.
- The receipt names no case or run and no filing event: `audit_head` is read
  after the governed write commits (`filing.py:216-224`), so a later event on
  the case can move it.
- `deliverable_opinions` / `deliverable_publications` (`schema.sql:242-266`) key
  on the text label.

## Decisions

1. **A revision is a stored, immutable object.** Migration `0015_revisions`:
   `deliverable_revisions (revision_id uuid PK, case_id, run_id, payload_sha256,
   saved_by, saved_at)`, UPDATE/DELETE/TRUNCATE refused by trigger, unique
   `(case_id, payload_sha256)`; the payload bytes are put in the blob store at
   `payload_sha256` inside the save unit. `deliverable_opinions.revision_id` and
   `deliverable_publications.revision_id` gain a foreign key to it `NOT VALID`
   (legacy label rows stay readable; new rows must reference a saved revision).
2. **`save_revision(conn, blobs, bundle, *, case_id, run_id, actor_id,
   narrative)`** is a governed write (`REVISION_SAVED`, WRITER). Inside the unit,
   under the case lock, it derives the canonical payload from the run's accepted
   artifacts in route order (the existing `canonical_payload` proof, moved to
   run on the unit's connection), adds the narrative, serialises canonically,
   stores the blob and the row, and returns the host-minted `revision_id`. The
   caller supplies no bytes and no digest. A run of another case is
   `RUN_NOT_FOUND`; an incomplete route `DELIVERABLE_PAYLOAD_INVALID`.
3. **The narrative is typed.** `narrative: list[Paragraph]`, each a list of
   spans: `{"text": BoundaryText}` or `{"figure": {"route_node_id",
   "citation_index"}}`. A text span containing an ASCII digit is refused
   `NARRATIVE_FIGURE_UNREFERENCED` -- every figure enters through a reference
   that resolves, at save, to an anchored citation of an accepted artifact in the
   payload (unknown node or index: `NARRATIVE_REFERENCE_INVALID`). The payload
   stores the resolved reference (`document_sha256`, `page`, `matched_text`) so
   the render shows the cited words, never re-typed numbers. At most 64
   paragraphs, 64 spans each, 2 000 characters per text span.
4. **Restrictions stay visible.** The payload carries each artifact's
   `qa_status`, `decision_scope` and limitations exactly as the record projects
   them; the render (unchanged purity) shows them beside the narrative. A route
   with a refused or blocked node cannot be saved (D2), so no refused claim is
   silently absent from a saved revision; this is stated in §57.
5. **Sign binds the stored revision.** `sign_opinion(conn, *, case_id, actor_id,
   revision_id: UUID)` reads the stored `payload_sha256` under the lock; no digest
   argument. A revision of another case is `DELIVERABLE_NOT_FOUND`; a frozen one
   `DELIVERABLE_ALREADY_FROZEN`.
6. **Freeze re-proves inside its own unit.** `freeze(conn, blobs, bundle, *,
   case_id, actor_id, revision_id)` under the case lock: reads the stored bytes
   (digest-verified by the blob store), re-derives the canonical payload for the
   same run and narrative in the same unit and requires byte equality
   (`DELIVERABLE_MOVED_SINCE_SIGNING` otherwise -- a withdrawn source, a changed
   bundle authority or a moved artifact refuses here, not after publication),
   requires the latest signature to bind that digest, refuses a signer
   (`APPROVER_NOT_INDEPENDENT`) and a second freeze. The publication row stores
   the revision's digest; the frozen payload is the stored blob.
7. **Filing's receipt names its own event.** `file_deliverable` returns a
   receipt with `case_id`, `run_id`, `revision_id` (UUID), `payload_sha256`, the
   three actors, `renderer_sha256` (SHA-256 of `server/deliverable/render.py`
   bytes, for 5.4a's verifier) and `filed_event_sha256` -- the `entry_sha256` of
   the `DELIVERABLE_FILED` audit link, read in the same transaction before
   commit (`governed_write` returns the link it wrote). `audit_head` is dropped.
8. **Races.** Every chain check already runs under the case lock inside the
   governed write; the new REDs prove it for save/sign/freeze/file across two
   cases and three actors with two connections each.

## Contract and scope

1. Use one closed, bounded v1 document per section, emitted from named Python
   models and checked by the existing TypeScript schema DSL. Regenerate the
   schema; extend exact key/shape parity and identity tests. Keep decimal values
   as strings and explicit unavailable values/reasons; never calculate in UI.
2. Each read authenticates and checks live case standing before data access.
   Malformed, missing and wrong-case identifiers retain private typed refusals.
   A requested run is the displayed run, independently of the latest run. An
   absent accepted object is empty/partial or unavailable, never a fixture.
3. Model reads the exact accepted CP-CF canonical pair through the existing
   acceptance reader and Task 5.2b's proven forecast projection seam. It exposes
   accepted identity, units/perimeter, per-case/period values and explicit
   unavailable reasons. A missing owner, stale pin, altered record or failed
   projection proof cannot release computed values. Do not infer covenant
   breaches, fabricate passports or label model-authored prose host-verified.
4. Report reads a saved revision through Task 5.3's store reader and live proof.
   Display exact route-ordered accepted narrative, typed figure references,
   restrictions and limitations. Selection must bind case/run/revision; no
   caller-supplied payload or detached digest substitutes for saved bytes.
5. Committee reads the persisted frozen object and exact filing receipt through
   the Task 5.3 chain. Never call a current reconstructed draft frozen/filed.
   Show signer/freezer/filer identities and the actual saved state. Reject a
   corrupted or mismatched chain before returning text. No arbitrary HTML is
   injected into the workbench; exact prose is rendered as escaped text.
6. Reuse the existing panels and accessibility patterns. Update transport,
   chrome, evidence lookup and case-event invalidation where their closed
   section lists require it. Enable a section only after its API, parser and
   real-object tests pass. Legacy demo fixtures are not integration evidence.
7. Reads grant no write authority. This slice adds no save/sign/freeze/file
   controls or commands: those require a separately specified request/receipt
   and server-side commit checks. Existing refused controls remain refused.

## Decisions

1. **Supported input, closed.** Top level: `opening`, `periods`, `drivers`,
   `contractual`, `units`, `perimeter`, optional `tolerance`. Any other key is
   `METHODOLOGY_INPUT_INVALID`.
   - `opening`: `cash`, `as_of_period_id`, `debt_by_facility[]` of
     `{facility_id, amount}` -- all required; unique `facility_id`.
   - `periods[]`: `{period_id, fiscal_year, case, days}` all required; `days`
     an integer string 1..366; unique `(case, period_id)`; order is the
     caller's and is the chain order per case.
   - `drivers[]`: `{case, period_id, status, stated_closing_debt,
     stated_closing_cash}` plus the movement fields below. Unique
     `(case, period_id)`; a driver for a pair not in `periods` is refused.
   - `contractual`: `amortisation[]` of `{case, period_id, facility_id,
     amount}`, unique by all four keys, each pair requested and each facility
     opened. `maturities` and `coupons` are **refused if present** until
     implemented (REPAIR_PLAN: unsupported contractual fields refuse).
   - `policy` is **refused if present** (sweep, minimum cash, revolver and FX
     behaviour are not implemented).
   - `units`: `{currency, scale}` -- `currency` three upper-case letters,
     `scale` one of `units`, `thousands`, `millions`, `billions`; carried
     unchanged to the output.
   - `perimeter`: a non-empty `BoundaryText` label of at most 64 characters,
     carried unchanged. The scenario is the period's `case`.
2. **Movements, and missing versus zero.** Every movement field is required on
   a `READY` driver row: `revenue, ebitda, cfo, capex, acquisitions_disposals,
   cash_interest, cash_taxes, distributions, issuance, optional_repayment, pik,
   capitalised_interest, fx_perimeter`. An explicit `"0"` is zero. An absent
   field makes that period **unavailable** with reason `DRIVER_FIELD_MISSING`,
   propagating forward in its case; a missing driver row for a requested pair
   is unavailable with `DRIVER_MISSING`. A row whose `status` is not `READY` is
   unavailable with `DRIVER_NOT_READY` (the refusal `FORECAST_DRIVER_NOT_READY`
   is retired from this path: one unready row must not refuse every other case).
   `financing_investing` is **no longer an input**: the host derives it (D3).
3. **The identities, exactly.** Per case-period, with contractual repayment
   the sum of that pair's amortisation rows (zero only when there are none):
   ```
   closing_debt = opening_debt + issuance + pik + capitalised_interest
                  - contractual_repayment - optional_repayment + fx_perimeter
   financing_investing = issuance - contractual_repayment - optional_repayment
                         - acquisitions_disposals
   closing_cash = opening_cash + cfo - capex - cash_interest - cash_taxes
                  - distributions + financing_investing
   fcf = cfo - capex - cash_interest - cash_taxes
   ```
   `fx_perimeter` and `acquisitions_disposals` are signed (a disposal is
   negative); every other movement must be non-negative or the request is
   refused. `accessible` cash equals closing cash (no restricted-cash field is
   supported; recorded in §54). Opening debt of the first period in each case is
   the sum of `opening.debt_by_facility`; later periods open at the prior closing
   (checked, `FORECAST_CHAIN_BROKEN` if the computed chain ever disagrees).
4. **Residual.** `residual_debt = stated_closing_debt - closing_debt`,
   `residual_cash = stated_closing_cash - closing_cash`. Either magnitude above
   `tolerance` (default `"0.001"`, in the request's units) makes the period
   unavailable with `RESIDUAL_UNRECONCILED` and propagates forward.
5. **Numbers.** Every numeric input is a JSON string matching
   `^-?(0|[1-9][0-9]{0,17})(\.[0-9]{1,6})?$` (no exponent, at most 18 integer
   and 6 fractional digits). Anything else -- float, int, bool, `null`,
   exponent, leading `+`, whitespace -- is `METHODOLOGY_INPUT_INVALID`. All
   arithmetic runs in one local `Context(prec=38, rounding=ROUND_HALF_EVEN,
   traps=[InvalidOperation, DivisionByZero, Overflow])`; the ambient context is
   never read. Amounts are output as strings quantized to 6 places; ratios
   quantized to 4 places.
6. **Ratios.** `gross_leverage = closing_debt / ebitda`, `net_leverage =
   (closing_debt - closing_cash) / ebitda`, `interest_coverage = ebitda /
   cash_interest`, `fcf_to_debt = fcf / closing_debt`. A zero or negative
   denominator gives `{"value": null, "reason": "ZERO_OR_NEGATIVE_DENOMINATOR"}`;
   otherwise `{"value": "<string>", "reason": null}`.
   `liquidity_runway_periods` is **not computed** (needs policy); omitted and
   recorded.
7. **Output.** `{status, units, perimeter, rows[], checks[]}`. `rows` holds
   exactly one entry per requested pair, in request order, each with its
   computed fields or `unavailable_reason`. `status` is `complete` only when
   every row is available. Output is canonical JSON (sorted keys, no spaces)
   byte-identical for the same request under any ambient Decimal context.
8. **Work factor** unchanged (40 periods per case, 6 cases, 40 facilities,
   `periods × cases × (1 + facilities) ≤ 100 000`), checked before parsing any
   numeric, plus at most 2 000 amortisation rows.

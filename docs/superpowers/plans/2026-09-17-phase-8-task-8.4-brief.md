## Contract and scope

1. `qualification/CORPUS.md`: one row per document — issuer, document,
   pathway(s) and module demand it serves, source (URL, EDGAR accession,
   date), local path, SHA-256 once admitted, status (in hand / to source /
   to author / not available), and the set(s) it is admitted into. The
   owner's answer key is listed as a *key source*, never as a document.
2. A "sourcing list for the owner" section: each "to source" row with the
   exact public location where known; the owner fetches, the coordinator
   admits under the document's own digest and records provenance in the
   set's `RESULT.md` header.
3. A "size" column: bytes of extracted text, and whether the document fits
   the request ceiling alone (which pathway tasks may run before Phase 10).
4. The register is regenerated, not hand-maintained, once documents are
   admitted: `scripts/corpus_register.py --report` reads every
   `qualification/*/qualification.json` and its documents' digests and
   emits the table; the hand-authored columns (source, status) live in a
   small `qualification/corpus.json` the script reads.

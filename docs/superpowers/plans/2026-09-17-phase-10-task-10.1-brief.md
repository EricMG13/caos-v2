## Contract and scope

1. **Selection is host-owned and pinned-fact-driven.** A node's delivery is
   the set of `(source_id, block_id)` chosen by
   `select_delivery(source_set, gate_record, module_id) -> Delivered` in a new
   `server/methodology/selection.py`, pure, from: the pinned
   `SourceSet.members`; the accepted CP-0 record's
   `content_to_module_map` row for `module_id` (`active_representation_ids`
   matched to members by `document_sha256` or the P-register's
   representation id as the record carries it; `evidence_demand` is prose
   and is carried, not interpreted); and one declared host rule per demand
   class recorded in `docs/DECISIONS.md` (this task's entry): a member named
   by the row is delivered whole; a member not named is not delivered; CP-0
   itself is delivered every member (`_source_preparation` unchanged); a
   consumer whose row names no member is refused `EVIDENCE_NOT_AVAILABLE`
   before any attempt. No model text chooses a block; no document prose
   chooses a block.
2. **Delivery is a stored fact per attempt.** Migration
   `<ordinal>_attempt_deliveries.sql`: `attempt_deliveries(attempt_id uuid PK
   REFERENCES run_attempts, delivery_sha256 text NOT NULL, recorded_at
   timestamptz NOT NULL DEFAULT now())` immutable like `0021`, plus
   `attempt_delivery_blocks(attempt_id uuid REFERENCES run_attempts,
   source_id uuid, block_id text, PRIMARY KEY (attempt_id, source_id,
   block_id))` immutable. `delivery_sha256 = canonical_sha256(sorted pairs)`.
   Written by `start_attempt`'s caller in the attempt's transaction, from the
   same `Delivered` `check_context` built (the pre-call unit returns it; the
   attempt unit re-derives and refuses `EVIDENCE_NOT_AVAILABLE` if the digest
   differs — the pins cannot have moved, so a difference is a fault).
3. **Every reader anchors against the row.** `verify_citations` is handed the
   attempt's stored delivery, never `captured_blocks`; `parse_response`'s
   `delivered` is the row's sources; the proof and the deliverable read the
   accepted attempt's row (`delivered_blocks(conn, attempt_id) ->
   dict[UUID, frozenset[str]]` in `executor.py`, replacing the
   `captured_blocks` call in T11's one reader). `captured_blocks` remains for CP-0 and for the
   run document's source list. The record (format v3) carries
   `delivery_sha256`; v2 records still verify against `captured_blocks`
   (they were delivered everything) and say so.
4. **Bounded line group.** `_blocks` packs consecutive lines of one page into
   one block while the joined text stays under `BLOCK_CHARS = 2_000`
   (declared in `ingest.py`, recorded in the extractor identity as
   `block_policy: "line-group-2000"`); a line over the width is its own
   block; block ids stay ascending and `block_ids_by_line` maps every line to
   its group. Anchoring reads line-to-block through the same function
   (`tests/test_awkward_evidence.py::test_admission_and_anchoring_share_one_line_to_block_numbering`
   stays green). Existing sources keep their identity and one-block-per-line
   rows; readmission is how a source gains the group (§44.4's pattern).
5. **Per-section bound and the retrieval step.** `invocation.py` declares
   `SECTION_BYTES = {"evidence": 640_000, "upstream": 256_000, "authority":
   …measured…}` inside `MAX_REQUEST_BYTES`; an evidence delivery over its
   bound refuses `CONTEXT_OVER_CEILING` with the unmet demand in the typed
   refusal's `clears` text (no document text), before any attempt; the
   single permitted narrowing is dropping members the CP-0 row lists as
   `priority` 3 or 4 (schema line 41) in that order, each drop recorded in
   the delivery row's `narrowing` column — never truncating a member. If the
   bound is still exceeded, refuse.

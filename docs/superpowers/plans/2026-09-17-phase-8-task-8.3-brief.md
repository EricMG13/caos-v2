## Contract and scope

1. `record_verdict` reads `SELECT DISTINCT model FROM call_outcomes o JOIN
   run_attempts a USING (attempt_id) JOIN artifacts USING (attempt_id) WHERE
   a.run_id = ANY(<the evidence's run ids>)` and refuses
   `VERDICT_BINDING_INVALID` unless every recorded model equals
   `evidence.model`; a run with no recorded model refuses too.
2. A unique violation on `qualification_verdicts` maps to
   `VERDICT_ALREADY_RECORDED` (new `RefusalCode`, served 409), by constraint
   name, not by message text.
3. `sign_verdict` requires the `Idempotency-Key` header the other commands
   require and writes a `command_requests` row (scope = nil UUID, command
   `SIGN_VERDICT`, the request digest over the document) in the verdict's
   transaction; a replay with the same key and digest is answered from the
   receipt; a different digest under the same key is the existing
   idempotency conflict. No case audit event: the immutable verdict row is
   the record.

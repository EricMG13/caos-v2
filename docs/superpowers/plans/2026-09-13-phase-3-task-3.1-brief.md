## The vendor contract the host must honour

- **Record:** one UTF-8 Markdown file; `sha256(text.encode("utf-8"))` is the
  identity downstream `upstream_artifacts_used[].sha256` names
  (`credit_os_v/navigation.py`, `handoffs.py`). `artifacts.artifact_sha256` is
  therefore the hash of the exact Markdown bytes.
- **Filename** `[issuer_id]_[module_id]_[YYYYMMDD].md`, derived by the host and
  passed to the validator.
- **YAML envelope** (restricted subset, vendor parser; no PyYAML): required core
  fields, issuer fields, and the routed-invocation fields `credit_os_*` plus
  `upstream_artifacts_used` that the model must copy unchanged.
- **Six H2 headings** in order; module registers per `SKILL.md` output profile
  (CP-0 P1–P8/T1–T8; CP-L10 TL10/20/23/30/40 .1–.4; CP-5 T5B.1–.8, T5.1–.9).
- **Statuses in the YAML:** `qa_status` Passed | Restricted | Blocked (Blocked is
  validator exit 3), `committee_status`, confidence score/band; readiness in CP-0
  T8.
- **Host-owned:** run id (vendor form `COS-<UTC created_at>-<run_id hex>`),
  profile, selection, route node, attempt (ordinal derived per run/node),
  invocation digest, authority-bundle digest, module id/name (catalog), issuer
  id/name, reporting period, analysis date, upstream refs; outside the Markdown:
  source fingerprint, route digest, build, manifest, adapter version.
- **Model-authored:** confidence, `qa_status`, `committee_status`, limitation
  flags, validation warnings, downstream consumers, body and registers.

## Stress-test corrections (targeted ultrathink, 13 September 2026) — binding

These supersede the sections above where they differ.

1. **Citations are bound to the Markdown (P0).** Every transported citation's
   `matched_text` must occur verbatim in the Markdown body and anchor exactly
   once in the delivered evidence; any citation that fails refuses the whole
   handoff (the Markdown cannot be edited, so §26's claim-level refusal does not
   carry over). Zero citations refuses. The accepted identity is the pair
   (`artifact_sha256` = Markdown, `record_sha256` = host record); citations are a
   host-verified attachment bound by `record_sha256`, not derived data.
2. **Identity is checked field by field (P1).** After the vendor checks, the
   host compares every host-owned YAML key type-exactly against
   `invocation_fields` (including `module_name`, `issuer_name`,
   `credit_os_run_id`, profile, selection and `credit_os_authority_bundle_sha256`),
   requires `credit_os_parent_run_id`/`credit_os_upgrade_source_sha256` absent or
   null, and requires `upstream_artifacts_used` to equal the host list exactly,
   with `sha256` present and closed item keys. A filename mismatch is
   `HANDOFF_IDENTITY_MISMATCH`. RED 4 is parametrised over every key.
3. **Attempt ordinal is stored (P1).** `run_attempts.ordinal`, assigned under
   `lock_run`, `UNIQUE (run_id, route_node_id, ordinal)`, at most 256 (the 257th
   attempt refuses). The ordinal is always passed explicitly to the vendor
   envelope functions, never recovered from the artifact. (Migration in 3.1b.)
4. **Vendor loader isolation (P1).** Compile verified bytes into privately
   namespaced modules under a lock with a `sys` shim; call only `validate_text`,
   `completeness_check.check(verified_skill_text, …)`, `navigation.parse_t8` and
   `envelope.build`/`digest`/`reproduce_and_match` with explicit arguments; never
   `content_errors`, `accept_snapshot` or `prepare`. RED 10 asserts `sys.path`,
   `sys.modules` (no generic vendor names), `meta_path`, `path_importer_cache`
   and `dont_write_bytecode` are unchanged and no `__pycache__` appears.
5. **The record and its reads (P1).** The record holds: Markdown hash, adapter,
   build, manifest, vendor `authority_bundle_sha256`, host `authority_digest`,
   full identity including ordinal and call-time upstream digests, projections,
   citations and refused count. `record_sha256` is written in the accept
   transaction (non-null for the new adapter at insert) and included in the
   accept-replay comparison. Readers verify both blobs and the binding, re-parse
   projections from the Markdown and compare, and re-anchor citations.
6. **Validated Blocked is terminal for the node (P1).** Host identity is
   checked first; a handoff that validates with `qa_status: Blocked` is stored
   as a diagnostic outcome for that attempt and the run ends BLOCKED — it is not
   retried as an ordinary refusal. Malformed or mismatched output stays an
   ordinary refusal.
7. **Text limits (P2).** Refuse U+2028, U+2029 and U+FEFF in the Markdown; use
   the vendor's frozen limits (front matter 262144 bytes, line 65536 bytes,
   file 26214400 bytes) instead of an invented bound.
8. **Subject values (P2).** At pin time, before gate approval: `issuer_id` must
   match the vendor `SUBJECT_KEY_RE`; subject values are single-line; invocation
   fields are emitted as double-quoted JSON scalars so they never parse as
   int/null/list.
9. **Migration 0011 (P2).** Format version 2 with its own fingerprint; version
   1 pins, fingerprints and gate-preview bytes stay byte-identical; no backfill
   UPDATE (immutability trigger). The COS run id is converted to UTC once and
   pinned in the version-2 input.
10. **Projections (P2).** CP-0 T8 refuses modules outside the pin as well as
    requiring coverage; LITE `committee_status` is checked against the route's
    screening-only scope where the vendor declares it; CP-5 receives the host's
    anchoring result as host-owned context, or the gap is recorded.
11. **Deliverable (P2).** Freeze binds (`artifact_sha256`, `record_sha256`) and
    renders from the store (3.1d).
12. **P3.** `validate_markdown` takes the verified `SKILL.md` bytes;
    `critical_cell_substrings_casefold` is enforced by the vendor, only
    `document_substrings_casefold` and `semantic_rules` are unimplemented;
    transport JSON refuses duplicate keys; RED 9 also asserts `__context__`
    carries no vendor text.

## Findings at base (`server/deliverable/package.py`)

- `verify_package` imports `server.deliverable.render`, so it cannot run without
  the repository; `render.py` itself imports `server.refusals`.
- No bound on archive size, member count, member size, compression ratio or
  compression method; duplicate member names and extra members are accepted.
- Not total: a non-object receipt raises `AttributeError`, `json.loads(payload)`
  and the render run outside any handler, and encrypted or unsupported members
  raise.
- `write_package` checks `exists()` then writes: two writers can both pass the
  check and one overwrites the other.

## Decisions

1. **The verifier is shipped inside every package.** Members, exactly and only:
   `payload.json`, `receipt.json`, `deliverable.html`, `render.py`,
   `verify_package.py`. `render.py` and `verify_package.py` are the exact bytes
   of `server/deliverable/render.py` and `server/deliverable/verify_package.py`
   at build time. A reader runs `python -I -S verify_package.py <package.zip>`
   in any directory with no dependency; it loads `render.py` from the archive,
   not from the path.
2. **`render.py` is stdlib-only.** It imports nothing from `server`; its refusal
   is a local `RenderRefused(ValueError)` carrying a code string, and the host's
   callers map it to `Refusal` where they did before. A test parses its AST and
   refuses any import outside the standard library.
3. **`verify_package.py` is stdlib-only, versioned and total.** `VERIFIER_VERSION
   = "1"`. `verify(archive: bytes) -> tuple[bool, str | None]` never raises for
   any input (a top-level catch of `Exception` returns a fixed reason, never the
   exception's text). Bounds, checked before reading any member body:
   - archive at most 64 MiB;
   - the central directory lists exactly the five names, once each (duplicates
     refused), with no directory entries, absolute paths, `..` or backslashes;
   - compression method `STORED` or `DEFLATED` only, no encryption flag;
   - declared uncompressed sizes: payload ≤ 32 MiB, export ≤ 64 MiB, receipt ≤
     64 KiB, `render.py` and `verify_package.py` ≤ 1 MiB each; each member read
     with a hard cap one byte past its limit, and a declared/actual mismatch or
     a ratio above 100:1 refused.
   Then the existing checks: receipt is a JSON object; payload hashes to
   `payload_sha256`; three distinct named roles; canonical pairs bind; the
   export re-renders byte-identically from the payload **using the archived
   `render.py`**, whose SHA-256 must also equal the receipt's
   `renderer_sha256` when the receipt carries one (5.3 adds it).
4. **Host `verify_package`** becomes a thin call into
   `server/deliverable/verify_package.verify`, keeping `Verification`.
5. **Exclusive creation.** `write_package` opens with `"xb"`; an existing path
   is `FileExistsError` without touching it, and two concurrent writers leave
   exactly one complete file.
6. **Deterministic build.** Fixed timestamps, sorted member order,
   `DEFLATED` at a fixed level; the same inputs build the same bytes.

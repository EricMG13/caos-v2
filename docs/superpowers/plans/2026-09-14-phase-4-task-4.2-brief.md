## Findings at base that bind this task

1. **`CANCELLED` is missing from the wire.** `wire.RunStatus` lacks it. The
   coordinator's dependency-consolidation slice (4.1c-d) adds it.
2. **Some store pins commit on their own.** `pin_route`, `pin_run_input` and
   `snapshot_source_set` each commit, so none can share a transaction with an
   audit event or an idempotency receipt.
3. **`admit_pack` extracts, then locks the case.** `test_extraction_precedes_case_lock`
   pins that order, so admission cannot run inside `governed_write`.
4. **`approve_gate` never checks run status.** It would release a gate on a
   terminal run.
5. **Two refusals map to 503 today.** `_STATUS` sends `RUN_INPUT_INVALID` and
   `HANDOFF_MODULE_UNSUPPORTED` to 503. Commands must classify caller mistakes
   before those codes can reach the caller.
6. **Form bodies need a parser the tree lacks.** FastAPI parses body and form
   parameters before dependencies. Starlette's `request.form` needs
   `python-multipart`, which is now authorized.

## Decisions

1. **Endpoints.** The table below lists them; paths are under `/api/v1/cases`.
   - `gate` is `source-set` or `research-plan`; anything else is
     `ENDPOINT_NOT_FOUND`.
   - The floor is the minimum case standing (`satisfies`), checked after the
     global role.

   | Command | Path | Request | Success | Floor | Audit action |
   |---|---|---|---|---|---|
   | Create case | `` | `CreateCase{title}` | 201 `CaseCreated{case_id}` | global ANALYST+ | `CASE_CREATED` |
   | Admit | `/{case}/sources` | multipart | 201 `SourcesAdmitted{case_id, source_ids≤50}` | WRITER | `SOURCES_ADMITTED` |
   | Select + pin route | `/{case}/runs` | `CreateRun{profile_id, selection_id}` | 201 `RunCreated{case_id, run_id, route_digest}` | WRITER | `RUN_CREATED` |
   | Pin subject | `/{case}/runs/{run}/input` | `PinRunInput{subject}` | 200 `RunInputPinned{run_id, source_set_version, input_fingerprint}` | WRITER | `RUN_INPUT_PINNED` |
   | Preview (GET) | `/{case}/runs/{run}/gates/{gate}/preview` | — | 200 `GatePreviewDocument{run_id, gate, content, preview_sha256, input_fingerprint, observed_at}` | READER | — |
   | Approve | `/{case}/runs/{run}/gates/{gate}/approval` | `ApproveGate{preview_sha256, input_fingerprint}` | 200 `GateApproved` | APPROVER | `GATE_RELEASED:<gate>` |
   | Start | `/{case}/runs/{run}/start` | `StartRun{input_fingerprint}` | 202 `RunWork{run_id, run_status, work}` | WRITER | `RUN_ENQUEUED` |
   | Retry | `/{case}/runs/{run}/retry` | `RetryRun{input_fingerprint}` | 202 `RunWork` | WRITER | `RUN_REQUEUED` |
   | Cancel | `/{case}/runs/{run}/cancel` | `CancelRun{}` | 202 `RunWork` | WRITER | `RUN_CANCEL_REQUESTED` |

   - **Create run and pin route are one command:** a run with no route is
     useless, so `start_run` and the pin share one unit.
   - **Start is its own command:** it is the only one that writes `run_work`.
   - **The subject pin snapshots live sources:** in the same unit. The
     SOURCE_SET preview shows the actual members and the approval binds them.

2. **Authority, derived by the server.**
   - Requests carry no actor, case, run or approver field. The actor comes from
     `actor_from_headers`; the case and run come from the path. A run of another
     case is `RUN_NOT_FOUND`.
   - **Order:**
     1. Identity: anonymous gets 401, with no connection opened and no body read.
     2. Path ids.
     3. Idempotency header.
     4. Visibility: no live standing gets 404 `CASE_NOT_FOUND`.
     5. Global role.
     6. Floor.
     7. Body.
     8. Governed write.
   - Case-scoped writes need global ANALYST+ as well as the floor. A global
     READER holding WRITER standing gets 403 `NOT_AUTHORISED`. Reads and
     previews need standing only.
   - A member below the floor gets 403.
   - A `NOT_AUTHORISED` raised by `governed_write` at commit (revoked
     mid-request) answers 404 `CASE_NOT_FOUND`.
   - Create case inserts the case, grants the creator ADMIN standing and writes
     `CASE_CREATED` in one transaction. That is a single-actor release under
     invariant 5.
3. **In-transaction store entry points (4.2c).** No behaviour changes; the
   committing wrappers call these, so existing tests stay green.
   - `routes.pin_route_in`, `run_inputs.pin_run_input_in` and
     `source_sets.snapshot_in`.
   - `gates.release_gate_in(conn, approval)`: the current write plus `lock_run`,
     refusing `RUN_NOT_RUNNING`.
   - `ingest.prepare_pack(documents, dispatch, limits) -> PreparedPack`, with no
     store access, and `ingest.admit_prepared(conn, blobs, case_id, pack)`.
   - Lock order stays case, then run, then `run_work`.
   - Blobs from a rolled-back admission are harmless content-addressed orphans.
4. **Admission.**
   - **Before reading the body:** `Content-Type` must be `multipart/form-data`
     and `Content-Length` must be present and at most `max_pack_bytes + 1 MiB`.
     Otherwise `REQUEST_INVALID`, or 413 `SOURCE_TOO_LARGE`.
   - **Parsing:** an async dependency runs after visibility and the floor, and
     calls `request.form(max_files=50, max_fields=0)`. The read transaction is
     closed first, so parsing and extraction hold no lock.
   - **Parts:** only parts named `document` are accepted. Each filename becomes
     `BoundaryText.of(name, limit=255)`, non-empty, used for display and never as
     a path.
   - **Dispatch and atomicity:** part content types are ignored; dispatch is by
     bytes (§44.6), and the §44 limits and the §47 child apply. The whole pack is
     admitted or none of it.
   - **Dependency:** add `python-multipart`, pinned and hashed, recorded in §51.
5. **Bounded JSON bodies.** `json_body(Model, max_bytes=16 KiB)` runs after
   identity.
   - Any failure is 400 `REQUEST_INVALID` in the refusal body, never FastAPI's
     422 that quotes the input.
   - Models are closed. `title` is at most 256 characters and passes through
     `BoundaryText`. The subject reuses `RunSubjectView` and `valid_subject`.
6. **Idempotency.**
   - **Header:** `Idempotency-Key` (a UUID) is required on every POST. If it is
     missing or malformed, the request is refused 400
     `IDEMPOTENCY_KEY_REQUIRED` before the body is read.
   - **Scope:** `(actor_id, scope, key)`, where scope is the case id, or the nil
     UUID for create case.
   - **Migration 0014:**

     ```sql
     CREATE TABLE command_requests (actor_id uuid NOT NULL, scope uuid NOT NULL,
       idempotency_key uuid NOT NULL, command text NOT NULL CHECK (command ~ '^[A-Z][A-Z_]{0,63}$'),
       request_sha256 text NOT NULL CHECK (request_sha256 ~ '^[0-9a-f]{64}$'),
       status smallint NOT NULL CHECK (status IN (200,201,202)),
       receipt jsonb NOT NULL CHECK (octet_length(receipt::text) <= 65536),
       created_at timestamptz NOT NULL DEFAULT now(),
       PRIMARY KEY (actor_id, scope, idempotency_key));   -- plus 0007-style immutability triggers
     ```

   - **Digest:** canonical JSON of `{command, case_id, run_id, gate, body}`. For
     admission, the body is `[{filename_nfc, sha256(bytes)}]` in part order.
   - **What is recorded:** only committed successes, inside the governed write's
     own transaction. Refusals commit nothing.
   - **Fast path:** after the visibility check, look up the key.
     - Same digest: replay the stored status and receipt with
       `Idempotency-Replayed: true`, writing nothing.
     - Different digest: 409 `IDEMPOTENCY_KEY_REUSED`.
   - **Backstop:** the last statement of the write is `INSERT … ON CONFLICT DO
     NOTHING`. A concurrent twin gets 0 rows, re-reads the row, rolls back its
     whole unit, and replays or answers 409.
   - **Residual:** a revoked member's rows are kept, but their replay answers 404.
7. **Stale previews and changed authority are conflicts with no provider call.**
   - **Approve** re-derives the preview under the case and run locks:
     - content moved or run transplanted: `GATE_APPROVAL_MISMATCH`;
     - a pinned member withdrawn: `EVIDENCE_NOT_AVAILABLE`;
     - run terminal: `RUN_NOT_RUNNING`.
   - **Start and retry**, inside the write:
     1. No pin: `RUN_INPUT_NOT_PINNED`.
     2. Pin build differs from the process bundle: `ORCHESTRATION_BUILD_MOVED`.
     3. `execution_input` refuses (not running, sources not live, gate not
        approved by a live APPROVER).
     4. Fingerprint differs from the body's: `COMMAND_EXPECTATION_STALE`.
     5. `enqueue_run` returns False: `RUN_ALREADY_STARTED`. `requeue_run` returns
        False: `RUN_NOT_STOPPED`.
   - **Route selection:** a pair outside `ADAPTER_ROUTES` is refused
     `ROUTE_NOT_ENABLED` before resolution. `require_adapter_route` then runs on
     the resolved route.
   - **Cancel:**
     - No work row: `enqueue_run` then `request_cancel` in one unit, ending the
       run CANCELLED.
     - Claimed and already requested: `RUN_CANCEL_REQUESTED`.
     - Terminal: `RUN_NOT_RUNNING`.
   - **No provider:** commands never call one. `server/api/commands/*` import
     only store, evidence and wire modules, and a test enforces that.
8. **Statuses** added to `_STATUS`:
   - 403: `NOT_AUTHORISED`.
   - 413: `SOURCE_TOO_LARGE`.
   - 409: `IDEMPOTENCY_KEY_REUSED`, `RUN_NOT_RUNNING`, `GATE_APPROVAL_MISMATCH`,
     `EVIDENCE_NOT_AVAILABLE`, `ROUTE_ALREADY_PINNED`, `ROUTE_PIN_TOO_LATE`,
     `RUN_INPUT_ALREADY_PINNED`, `RUN_INPUT_TOO_LATE`, `RUN_INPUT_NOT_PINNED`,
     `RUN_ALREADY_STARTED`, `RUN_NOT_STOPPED`, `RUN_CANCEL_REQUESTED`,
     `COMMAND_EXPECTATION_STALE`, `ORCHESTRATION_BUILD_MOVED`.
   - New codes, each with `CLEARS` text: `REQUEST_INVALID`,
     `IDEMPOTENCY_KEY_REQUIRED`, `IDEMPOTENCY_KEY_REUSED`, `RUN_INPUT_NOT_PINNED`,
     `RUN_ALREADY_STARTED`, `RUN_NOT_STOPPED`, `ROUTE_NOT_ENABLED`,
     `COMMAND_EXPECTATION_STALE`.
9. **Audit pairing.** `governed_write` is used unchanged, with the domain `_in`
   call first and the receipt insert last. The payload carries the domain ids
   and digests plus `request_sha256`. State, run events, `run_work`, the audit
   link and the receipt commit together or not at all.
10. **`Chrome.actions`.**
    - **Shape:** `list[ActionView{action: ActionName, refusal: RefusalBody | null}]`.
    - **Per section:**
      - Directory: `CREATE_CASE`.
      - Upload: `ADMIT_SOURCES`.
      - Run: `CREATE_RUN`, `PIN_RUN_INPUT`, `APPROVE_SOURCE_SET`,
        `APPROVE_RESEARCH_PLAN`, `START_RUN`, `RETRY_RUN`, `CANCEL_RUN`. With no
        displayed run, the run-scoped actions are refused `RUN_NOT_FOUND`.
      - Analysis: none.
    - **How they are computed:** pure functions in
      `server/api/commands/availability.py`, over the facts each read already
      holds, in decision 7's order. They are advisory; the command rechecks at
      commit.
    - **Run section additions:** `RunView.work: WorkView{state, stop_code,
      cancel_requested} | null` and `RunBody.route_choices` (at most 16, from
      `ADAPTER_ROUTES`).
11. **Wire and DSL.**
    - Command models live in `server/api/wire.py` as `V1_COMMANDS`, and
      `wire_schema()` prints documents, commands and `RefusalBody`.
    - `frontend/src/wire/v1/commands.ts` declares receipts, previews and request
      shapes. Both contract tests cover them.
    - Every receipt and preview is validated in the browser; nothing is cast.
12. **Frontend.** 4.2 wires only what the journey needs; 4.4 owns refresh
    semantics.
    - `frontend/src/app/commands.ts` POSTs with one `crypto.randomUUID()` key per
      user intent, reused on a network retry and replaced after any answer.
    - Controls render from `chrome.actions`: present and refused, never hidden.
      - Directory: create case.
      - Upload: admit files.
      - Run: route choice, subject form, exact preview text, approve, start,
        retry and cancel.
    - After a success, one plain refetch.
13. **CSRF and origin, split with 4.5.**
    - 4.2 adds no CORS middleware, requires exact content types, and makes the
      custom `Idempotency-Key` header mandatory, so a cross-site simple form POST
      is refused before any effect.
    - 4.5 adds Origin and `Sec-Fetch-Site` checks, the cookie and SameSite
      policy, the trusted edge and CSP.
14. **IO budgets.** Each command module declares a budget, measured by a test.
    - Create case, route, input, approve, start, retry and cancel: fixed.
    - Admission: fixed plus 4 per document.
    - A replay: at most 3.
    - Preview: `PINNED_INPUT_IO + 2`.
    - The Run read gains 1 for the work row.

## Authority trace

| # | Hazard | Deciding predicate | Result |
|---|---|---|---|
| T1 | Body names another actor or approver | Models have no such field; `actor_id = actor.user_id` | Impossible |
| T2 | Client role header in production | `actor_from_headers` reads groups only (§22) | No escalation |
| T3 | Preview read, then content or run changes | `release_gate_in` re-derives under locks | 409 `GATE_APPROVAL_MISMATCH` |
| T4 | Preview read, then a pinned source is withdrawn | `_sources_live` at approve and start | 409 `EVIDENCE_NOT_AVAILABLE` |
| T5 | Approver revoked before approving | `_require_standing` under the case lock | 404 |
| T6 | Approver revoked after approving, before start | `execution_input` checks the approver's standing | 409 `GATE_APPROVAL_MISMATCH` |
| T7 | Writer revoked between precheck and commit | `governed_write` | 404; nothing committed |
| T8 | Revoked after enqueue | The worker's `execution_input` at each attempt | No call |
| T9 | Same key, different body | Digest comparison | 409 |
| T10 | Concurrent twins, including create case | Primary key plus `ON CONFLICT DO NOTHING` | One effect |
| T11 | Replay by a revoked member or nonmember | Visibility check before lookup; key includes the actor | 404 |
| T12 | Replay of a stale start after cancel | Replay returns the original receipt and writes nothing | No second enqueue |
| T13 | Start with unpinned or foreign-build input | Classification in decision 7 | 409, never 503 |
| T14 | Cross-site form POST | Missing `Idempotency-Key` | 400 before the body |
| T15 | Browser disconnects mid-command | The unit commits or rolls back whole | No paid call touched |
